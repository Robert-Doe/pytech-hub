Prerequisite 02 of 04

Pointers & References

The single idea that makes every non-array data structure in this course possible: a value that doesn't hold data, it holds directions to data.

01

The Big Analogy

A sticky note with an address on it, vs. the house itself. Suppose I hand you a sticky note that says "742 Evergreen Terrace." That sticky note is not a house. It has no rooms, no furniture. But it tells you exactly where to go to find one. If you drive there, knock, and repaint the door, the house changes — but your sticky note is still just as valid, still says the same address, and now points at a freshly painted house.

A pointer (C/C++) — or the hidden reference every Python variable already is under the hood — is that sticky note. It is a small, fixed-size value (an address) that tells you where to find a much larger or more important value. Copying the sticky note is cheap — you're not rebuilding the house, just re-writing seven digits. That's the entire reason linked structures (Module 05 onward) can insert a new node without moving every other node: they just re-point a few sticky notes.

02

What Happens, Step by Step

  1. A value is stored somewhere — call its address 0x1000.
  2. You take its address — in C/C++, with & (int *p = &x;). This does not copy x; it creates a new, small value: the number 0x1000, typed as "address of an int."
  3. You dereference the pointer — *p means "go to the address stored in p, and treat what's there as an int." This is the "drive to the address on the sticky note" step.
  4. A C++ reference (int &r = x;) is a pointer with the danger sanded off: it must be bound to something at creation, can never be null, and never needs an explicit dereference — the compiler inserts the "go to the address" step for you every time you use r. Same mechanism, safer interface.
  5. Python has no visible pointer syntax — but every name is already a reference. a = [1,2,3]; b = a does not copy the list; b is a second sticky note pointing at the same house. Mutating through b is visible through a. This single fact explains almost every "why did my Python list change unexpectedly" bug a beginner hits.
03

A Concrete Map of State

int x = 99; int *p = &x; int **q = &p;

addr 0x2000 — "q"

value: 0x1000

addr 0x1000 — "p"

value: 0x1088

addr 0x1088 — "x"

value: 99

q points at p. p points at x. Three separate boxes. *p reads 99 (one hop). **q also reads 99 (two hops). Changing *p to 5 changes x. Changing p itself would re-point it at a different int entirely — x is untouched.

One confusion to kill early

A pointer and the thing it points to are two separate pieces of memory, each with its own address. p lives somewhere; *p lives somewhere else entirely. Beginners often picture the pointer as the box it points to — draw it as two boxes with an arrow, always, the way section 03 above does, and this stops being confusing.
