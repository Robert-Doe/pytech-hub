Prerequisite 04 of 04

C, C++ & Python — a Rosetta Stone

Every module ships the same structure three times. This page exists so no module has to stop and explain malloc vs new vs a Python list — you'll already know the shape.

01

The Big Analogy

Three translations of the same instruction manual. Imagine a piece of furniture that ships with an instruction manual printed in three languages. The furniture — the actual data structure — is identical in all three: same shape, same screws, same final result. What differs is how explicit each manual has to be. The German manual (C) tells you the exact torque for every screw and makes you supply your own screwdriver. The English manual (C++) gives you sensible defaults but lets you override any of them. The picture-only manual (Python) just shows you the finished picture and trusts a machine to work out the screws for you. Read one confidently, and the "translation" to either of the others is mostly just vocabulary.

02

What Happens, Step by Step

  1. C is compiled, ahead of time, to machine code — gcc file.c -o file produces a standalone binary. There is no runtime helping you; every byte of memory you use, you asked for.
  2. C++ is also compiled ahead of time — g++ file.cpp -o file — but adds classes, references, and RAII (objects that clean up after themselves when they go out of scope) on top of everything C already gives you.
  3. Python is interpreted — python3 file.py reads and runs your source directly (technically compiling to bytecode first, invisibly). No separate build step, and the runtime manages memory for you.
  4. Every module's C and C++ files declare a "shape" in a header (.h / .hpp) separately from the implementation (.c / .cpp) — Python has no header step; the .py file is both at once.
03

A Concrete Map: the Same Idea, Three Ways

C — a growable list of ints, manually 
// caller owns the memory; must call free()
int *data = malloc(capacity * sizeof(int));
data[0] = 42;
free(data);
C++ — same idea, RAII-wrapped 
// destructor frees automatically when v goes out of scope
std::vector<int> v;
v.push_back(42);
Python — same idea, fully managed 
# garbage collector frees it whenever nothing references it
v = []
v.append(42)

All three end up with one int, 42, reachable through a name. What differs is who is responsible for the memory — you, the compiler-generated destructor, or the garbage collector. That responsibility question is the throughline of every DECISIONS.md in this course.

05

Limits of This Page

Not covered here

  • C++ templates / generic programming
  • Python's data model internals (__dunder__ methods) beyond what a module needs
  • Build systems, package managers, or IDE setup — every module documents its exact compile command instead

What this page gives you

  • Enough shared vocabulary that a module's three source files read as "the same thing, three accents" instead of three unrelated languages
  • Why the C version of a module is usually the longest and the Python version the shortest — same logic, different amounts the language does for you
  • The exact compile/run commands every module's "Run It" section will reuse verbatim
One confusion to kill early

C++'s std::vector, Python's list, and similar built-ins are not what you'll be building in Module 03 — this course builds a dynamic array from raw malloc/pointers first, precisely so those built-ins stop being magic. Once you've built one, using the standard library's version is just "using the production-grade version of the thing I now understand."
